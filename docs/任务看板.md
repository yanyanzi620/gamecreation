## 4. 任务卡模板（派活时照这个填）

```markdown
## 任务：<一句话说清要做出什么>
- 目标：玩家能感知到的变化是什么（不要写实现方案）
- 输入物：要读的文件 / 截图 / 现有参数
- 约束：不许动的文件、必须保持的口径（例如"不许在模块里写死数值"）
- 验收：可命令行复跑的标准（引用系统设计书 §9 的模式 + 判定口径）
- 交付：改动的文件清单 + 关键数字 + 截图（如涉及画面）
- 禁止：明确列出"不要顺手做的事"（例如不要重做地图、不要改 balance 其他项）
```

**派活三不要**：不要给"优化一下手感"这种无验收的描述；不要一次派跨 3 个目录的任务；不要在任务里夹带"顺便重构"。

## 5. 已明确的用户口径（写代码时不许违反）

1. 地图要铺满、有细节、有压迫感；**形状必须是器官本身**，不是方形场地。
2. 一屏大致装下**一个半区**（现在是 68% 叶宽，已认可更近）。
3. 叶形**上宽下窄**（与真实解剖相反，用户口径）。
4. 肺泡要大（玩家约占肺泡面积 10% 量级），通道可大可小、随机。
5. 病毒必须是**粒子态、复制式扩张**；打上去是"一片片被吃掉"。
6. 射流**打不穿墙**、**被阻隔带挡住**；阻隔带必须在单元正前方、固定长度、闪烁后生效。
7. 跳跃链 = 单点传播、前方扇形随机落点、**无视阻隔带**。
8. 病毒**不要数量上限**，但必须保住帧率。
9. 画面必须**实时刷新**（已关掉低功耗模式与帧率上限）。
10. 数值集中一处、带注释；**不要堆屎山**，新功能先找已有的缝。
