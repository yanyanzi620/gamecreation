# 病毒模型与攻击机制（实现版 v0.3）

> 对应代码：`scripts/world/virus_population.gd`、`scripts/units/tools/jet_system.gd`、`scripts/units/tools/purge_aura.gd`
> 演示场景：`scenes/demo/virus_showcase.tscn`


> **所有数值统一在 `scripts/core/balance.gd`**。本文出现的数字只是当前的默认值，改数值请改那个文件。

# 1. 表示

病毒**不是场，也不是节点云**，而是一堆粒子。

| 层 | 内容 |
|---|---|
| 粒子 | `位置 / 半径 / 年龄 / 冷却 / 形态 / 主轴角 / 病毒ID` |
| 病毒 | 一组粒子 + 一个主轴角 + 一个形态枚举 |
| 边界 | 不存曲线，边界就是**密度前沿** |

容量：`MAX_LIVE 4200` / `MAX_CORPSE 1200`，渲染走单个 MultiMesh（1 次 draw call）。

## 2. 三种形态

三者共用同一套复制规则，**差别只在三个参数**：方向权重表、每格容量、步长。

| 形态 | 枚举 | 格容 | 方向权重（正前 / ±45° / 侧 / 反） | 步长 | 长成什么 |
|---|---|---|---|---|---|
| 圆周 BLOB | `KIND_BLOB` | 10 | 1 / 1 / 1 / 1 | 14~26 | 不规则圆盘，密实 |
| 带状 BAND | `KIND_BAND` | 6 | 6.5 / 1.2 / 0.5 / 0.3 | 14~26 | 连续长条，长直段 + 偶尔折线 |
| 跳跃链 CHAIN | `KIND_CHAIN` | 2 | 不走邻格（单点随机落） | **70~150** | 一团散开的点阵，整体往前推 |

**链和带怎么区分**（关键不在参数微调，而在**生长方式根本不是一回事**）：

| | 带状 BAND | 跳跃链 CHAIN |
|---|---|---|
| 生长方式 | 逐格邻接：一颗挨着一颗长 | **单点传播**：直接往空中随机落一颗 |
| 步长 | 14~26（贴在一起） | **70~150**（一次跳很远） |
| 形态 | 连续成片，有带宽 | 散开的点阵，点与点之间全空 |
| 遇到阻隔带 | 被拦住，只能从两端绕 | **无视封堵**，照样落在带子后面 |

链的落点规则：`主轴 ±38°` 的扇形内，随机取角度和距离，直接 `_spawn` 一个点。
它既不沿地面走，也就不需要「方向权重」和「邻格容量」——这两套只服务 BLOB / BAND。

**打分公式**：`score = 方向权重 × (格容 - 该方向邻格已有粒子数)`，取最大者生长。

这个公式同时满足两件事：
- 形状由权重主导（带只往前长、链只往前长）；
- 再满的格子也挡不住一个**完全空的缺口** —— 这就是「填洞」。

## 3. 生长三条铁律

1. **复制式扩张**：冷却结束 → 生一个新粒子，本体不变大。
2. **朝最空的邻格生**：八方向各探 30 单位，前沿外推 + 缺口回填。
3. **无终身配额**：只受冷却（1.4~2.5 秒）+ 格子容量约束。

> 第 3 条是踩坑换来的：有过「配额制」的版本，缺口边缘的老粒子配额用完就不再繁殖，
> 结果咬痕永远填不上。配额是错的，空间才是唯一约束。

链形态不参与上面这套邻格逻辑：它每次只做一件事 —— **往前方的扇形区域里随机落一个点**。
所以它永远填不满、永远有空洞，这也是它和「带」在画面上一眼可分的原因。

## 4. 攻击与控场

| 手段 | 代码 | 定位 | 参数 |
|---|---|---|---|
| 射流 | `jet_system.gd` | 主动、定向、高频 | 470 长 / ±16° / **0.22 秒**（按住左键连发） |
| 净化场 | `purge_aura.gd` | 被动、贴身、持续 | 半径 108 / 55 个每秒 |
| 养分拾取 | `purge_aura.gd` | 自动、无操作 | 半径 **200** / 45 个每秒 |
| 阻隔带 | `virus_population.gd#place_block` | 主动、封路、**消耗 30 养分** | 右键拖拽 / 200 长（两端被肉壁裁短）/ 0.45 秒生效 / **60 秒**自溶 |
| 引信 | `virus_population.gd#add_fuse` | 主动、定点清场、最贵 | **空格拖拽** / 40 养分 / 5 秒冷却 / 维持 3 秒 |

- 射流：左键**点一次 = 一发**（按下边沿触发，按住不连发），锥内 live 全转尸体。
- 净化场：站在病毒里也不会被瞬间淹没，是「近身安全区」。
- 养分拾取：只吃**躺了 1 秒以上**的尸体，所以射流划过的地方能先看到疤，再变成光点飞回来。

## 5. 阻隔带

规则（v2 · 拖拽式释放）：

- **按住右键拖拽定位，松开落位**：拖拽方向 = 你要挡的那条来路。
- 带子**恒垂直于**「单元 → 光标」连线；拖多远 = 带子落在多远，最近 `BLOCK_RANGE_MIN 90`、最远 `BLOCK_RANGE_MAX 560`。
- 满长 `BLOCK_LEN 200`（原 400 的一半）。**两端会被肉壁裁短**（`OrganMap.clip_span`），
  带子永远不许插进组织里。裁到短于 `BLOCK_MIN_USABLE 70` 就放不下来（预览打橙叉）。
- 释放后**闪烁 0.45 秒才生效**（黄色闪烁 = 还没封住，青色 = 已封住）。
- 生效前病毒已经穿过去 → 那颗病毒只是**减速**（繁殖冷却 ×2.4）。
- 生效后病毒无法穿过；带子**有限长**，所以病毒从两端绕过去 —— 这就是圆盘病毒撞墙时的「绕射」。
- **病毒和玩家都拦**，但只有「已生效」才拦：闪烁期病毒只是减速，玩家也能直接穿过去。
- **60 秒**后自溶，缺口重新打开（30 秒时刚封好就到期，玩家根本来不及用它做战术规划）。
- **同时最多 6 条**（`BLOCK_MAX`）+ 0.5 秒冷却。只有养分限制的话，收入一高就会满地图糊墙，
  战场被墙铺满之后病毒无路可走、玩家也无路可走。
- 玩家撞带时沿带子滑动，不会被完全钉死。
- **与「器官隔离」是两件事**：阻隔带永远不断血，所以不会加速坏死。

实现方式：生长落点前做一次线段相交判定。被拦住的方向在 `_pick_dir` 里直接跳过，
于是「最空的邻格」会自动变成沿带子方向或带子两端 —— 绕射是**涌现**出来的，不需要单独写算法。

**「看到的就是放下的」**：落位几何只算一次 —— `VirusPopulation.resolve_block()`，
瞄准预览（`units/tools/aim_preview.gd`）和真正落位都调它。预览里两端出现黄色横杠，
就表示那一段被肉壁吃掉了。

**实测分布**（`scripts/debug/aim_probe.gd`，7680 次随机落位）：

| 指标 | 数值 | 含义 |
|---|---|---|
| 放得下来 | 82.6% | 其余是「贴着墙站」或「裁完太窄」 |
| 被肉壁裁短 | 83% 的成功落位 | 肺泡腔室约 240 宽，200 长的带子基本都会被裁 |
| 实际平均长度 | 127 / 200 | 带子贴着腔室形状走，而不是凭空插进肉壁 |
| 违规（端点进肉壁 / 整条穿墙） | 0（端点 3/6341 为栅格与轮廓半格偏差） | |

## 5.5 养分经济

养分是唯一资源，来路只有一条：**病毒尸体**。

```
病毒死亡 -> 尸体(灰) --躺 1 秒--> 进入拾取范围 -> 白色光点飞向单元 -> 养分 +1
```

- 尸体**被吃掉的那一瞬就从池里删掉、也从画面消失**（`_kill` 里补了槽位重写；
  以前漏了这一步，会出现「尸体已经变成养分、地上还留着一个鬼影」）。
- 光点是**白色**的：金色会和病毒撞色，玩家分不清哪个能吃、哪个会传染。

- 拾取半径 **300**，比射程 470 小：打出去的远端那一半收不回来，必须往前走一步才吃得到。
- 拾取是自动的，玩家不需要任何操作；光点以 460 px/s 飞向单元，到位才入账。
- **掉落是概率事件**：只有 `CORPSE_CHANCE = 0.18` 的病毒会留疤，其余直接消失、不给养分。
  以前「每颗必掉」时，连打两发就满地白点、拾取速率还追不上，观感上像战场被垃圾糊住。
- 拾取**不限速**（`PICKUP_PER_SEC = 0`）：范围内躺够时间的尸体有多少吸多少，
  只有「同时在场光点 ≤ 70」这一个上限。满了就先不吃，尸体留在原地等下一帧，不丢养分。
- 上限 70 个光点同时在场。**先算「还能带几个」再决定吃几个** —— 早期版本是先吃再塞，
  结果满员时光点生成不出来、尸体却已经从池里删掉了，那部分养分是凭空蒸发的。
- 尸体躺不满 1 秒不吃 —— 保证「刚打完那一瞬间」还能看到疤。
- 实测（`--econ`，站感染源连续开火 20 秒）：击杀 **170 颗/秒** → 掉落 **≈38 颗/秒** →
  养分 **≈37/秒**。这就是 `*_COST` 的定标依据。
- 支出：**阻隔带 60 养分 / 条**，**引信 80 养分 / 枚**（约等于 1.6 秒 / 2.2 秒的持续作战收入）。
  放不出来就是放不出来，不会自动降级。

这条链路把「攻击」和「控场」绑到了一起：打得越多 → 养分越多 → 越封得住；
但封得越多 → 越打不到近处的病毒 → 养分收入下降。这是**故意留的负反馈**。

**实现注（踩过的坑）**：`place_block` 里 `a`/`b` 是沿**带子长度方向**铺开的，所以带子的法线是 `d`，不是 `perp`。
早期把法线存成了 `perp`，导致相交判定算的是「沿带子方向」的坐标 —— 两侧的点会得到同一个值，
永远判不出穿越，**阻隔带实际上一直没生效，纯粹是画上去的一条线**。
直到给玩家加碰撞、拿它去撞带子才暴露出来。

## 5.6 引信

**按住空格拖拽定位，松开落位**：落点距单元最远 `FUSE_RANGE_MAX 420`（超出就夹到 420）。
落点若在肉壁里，会往最近的流明吸一次（`OrganMap.nearest_free`），80 内吸不到就放不下来
（预览打红叉）。维持 3 秒。它身上挂两个圈，作用完全不同：

| 圈 | 半径 | 对谁生效 | 效果 |
|---|---|---|---|
| 内圈 杀伤 | 125 | 圆盘 / 带状 / 链，**全部** | 进圈即消融，留尸体 |
| 外圈 引力 | 330 | **只有跳跃链** | 每秒被拽 250 单位，拉进内圈后被消融 |

设计意图：

- 圆盘和带状是「面」，用射流和阻隔带去处理；引信对它们只能啃一个小洞，不划算。
- 跳跃链是「散点」，射流扇形打不全、阻隔带拦不住 —— 引信是它唯一的解：
  **把散在 220 半径里的点吸到一个 85 的圈里，再一起烧掉。**
- 成本 80 养分 + 6 秒冷却 + 同时最多 3 枚，是全套手段里最贵的一发，逼玩家在「现在清场」和「留着养分封路」之间选。

> 实现上，链粒子被拽动时要同步维护粗格占用（先 `_cell_remove` 再 `_cell_add`），
> 否则格子计数会和真实位置脱节，之后的繁殖判定全错。

## 6. 消除与视觉三层信息

| 颜色 | 含义 | 生命周期 |
|---|---|---|
| 绿 / 琥珀 / 品红 | 活病毒 | 持续复制 |
| 灰 | 尸体（战斗疤痕，**掉落概率 18%**） | 30 秒衰减 |
| 空腔 | 被打空的区域 | 数秒内被绿色回填 |

尸体**不占格子、不扩散、不复生**，所以回填时可以透过尸体生长 —— 视觉上就是
「绿色从灰疤里重新长出来」。

## 6.5 贴墙滑行 & 射流不穿墙（v0.4 补）

**玩家移动**：判定不再「撞墙就只走一个轴」。现在是**角度探测**——
以输入方向为基准，按 0/±16/±34/±52/±70/±88 度逐档试探，第一档走得通就按它位移（每档还试一次半步，防止窄口整帧作废）。
效果：斜墙、肺泡内壁、凹角都能顺着走；实测同样斜推 3 秒，路径长度约为旧逻辑的 2.1 倍。

**射流**：一发不再是一个纯几何扇形，而是 **`JET_RAYS = 15` 条射线**（`_fan_rays`）：
每条射线按 12 单位步进，`organ.blocked()` 一碰到肉壁就停在该点，记下每条射线的实际长度。
这份长度表**同时用于判命中与画扇形**，所以「画得到的地方才清得到」，不会隔墙杀毒。
代价：一发约 600 次线段判定，2 Hz 触发，可忽略。

**阻隔带也是墙**：`_fan_rays` 每条射线再叠一次 `_band_reach()`，
只有「已生效（实线）」的带子才截断射线，闪烁期照旧穿过（与「生效前穿越只减速」同一口径）。
因此射流打在自己刚铺的带子上会当场停住 —— 带子既是病毒的墙，也是自己的弹道遮挡。
日志里有 `band_clip` 计数，实测同一位置：开火前 `max_reach=396`（打到胸膜）、
铺带后 `max_reach=228`（停在带子上），锥外病毒存活。

**残余病毒不长的问题**：一次繁殖失败时的冷却现在只重试 `VIRUS_RETRY_MIN~MAX`（0.18~0.42 s），
而不是原来的整个代际（1.05~1.85 s）。另外 `_pick_dir` 加了第二段探路：
本地粗格塞满时允许用 `VIRUS_ESCAPE_PROBE = 60` 的距离往远处空位甩一颗（落子距离同步放远）。
于是「小股病毒坐在一个满格里」不会长时间僵住，落子失败（池满/压墙）也不会白丢一个代际。


# 6.6 病毒不再有数量上限，单帧开销有硬上限（v0.5）

**池结构换了**：以前是「固定 7800 槽 + free list + 每帧扫全池」，现在改成
**连续存储 + 尾部交换删除 + 按需扩容**（`_grow_pool`，初始 16384，不够按 8192 起、1.4 倍递增）。
`MAX_LIVE` 这个常量已经删掉——能长到多少只由**密度上限**（`BLOB_CAP` 等）和地图空地决定。

**时间全部改成「绝对到时」**：`_due[i]`（下次可复制）、`_die[i]`（尸体消失）都是时刻而不是倒计时。
好处是没被扫到的粒子不会算错，也**不需要每帧给每颗做减法**。

**单帧三道上限**（都在 `balance.gd`，全部只影响性能、不影响玩法）：

| 闸门 | 作用 |
|---|---|
| `VIRUS_WORK_BUDGET` × 最多 6 | 每帧扫多少个槽（`_sweep` 轮转游标） |
| `VIRUS_SPAWN_BUDGET` | 每帧最多提交多少颗新粒子，超了推到下一帧 |
| `VIRUS_QUERY_BUDGET` | 净化/拾取每次最多扫多少槽（同一个轮转游标） |

**两处真正的热点优化**：
1. 繁殖探路不再调 `organ.blocked()`（轮廓段精确判定，一次 ~5µs，每颗要 8~16 次），
   改成栅格采样 `solid_xy()` / `line_free()`。探路距离 30 < 最薄隔膜 46，所以单点采样就等价。
2. **塞满 ≠ 撞墙**：`_pick_dir` 现在区分两种失败，密度塞满的粒子走长退避 `VIRUS_SATUR_COOL`（1.8~3.4s），
   而不是每 0.3 秒重试一次。饱和区本来也长不出东西，这一步砍掉了 4 倍的无用功。

**实测（`-- --stress`，只跑模拟的 60 秒游戏时间）**：

| 存活数 | 优化前单帧 | 优化后单帧 |
|---|---|---|
| 4.8k | 7.54 ms | 0.75 ms |
| 8.3k | 4.78 ms | 1.41 ms |
| 20.2k | （旧版在 6000 就停繁殖） | **3.50 ms**（最差 5.4~7.3ms） |

`upload` 部分稳定在 0.1~0.25ms/帧（整块 buffer 上传，与数量弱相关），60fps 的 16.7ms 预算还留着大量余量。


# 7. 已知待调项

- 射流 0.22 秒一发（按住连发）是否过强：单发清除量约 4~5% / 团，连发时 DPS 约为旧版的 2.3 倍，需看实测 TTK。
- 带状宽度（当前约 200 单位）是否还需要更窄。
- 链的点间距（32~52）是否太稀。
- 阻隔带 200 长（还要被肉壁裁短）/ 60 秒寿命 是否合适；是否需要限制同时存在的数量。
- 墙体 / 器官边界交互尚未实现（粒子会直接贴到 arena 边界）。

| 阻隔带能放几条 | `BLOCK_MAX` | 现在是 6；这条比价格更能封死「糊墙」打法 |

| 引信吸多快 | `FUSE_SPEED` | 250 时链基本逃不掉 |
